---
title: "E02-228 A value isn't one of the allowed values"
description: "An import refused a value because the attribute takes only the values on its list of allowed values. What the log file says today, for products and custom entities, and how to fix it."

---
An import refused a value because the attribute takes only the values on its list of **Allowed values**, and the value is not on that list. A product is imported without that field's value; a custom entity record is not imported at all. To fix it, add the value to the list, let the attribute take custom values, or change the value in your data, and import again.

**The code E02-228 no longer appears.** Log files used to name this problem by that code. Today the log file says what happened in words, on the row, record and field it is about.

## What the log file says

The dataset's log file has an entry on the attribute's field, with the row and the record. What it starts with depends on what you imported:

| You imported | The entry | Its message |
| --- | --- | --- |
| Products | A warning: the product was imported, without this field's value | *The record was imported without this field's value. "Blue" isn't one of this field's options. Change the value in the file, or add the option to the field, and import again.* |
| Custom entity records | An error: the record was not imported | *Couldn't import the record. "Blue" isn't one of this field's options. Change the value in the file, or add the option to the field, and import again.* |

The quoted value is the one from your file, and the field's *options* are the values on its **Allowed values** list. Where to find the log file, and what its other columns show: [Reading a log file](/en/troubleshooting/background-jobs.html#reading-a-log-file).

## Fix it

Only a **Text** attribute has a list of allowed values. Choose by whether the value is right and the list is missing it, or the value is wrong.

| The value is… | Fix | Where |
| --- | --- | --- |
| Right, and should be one of the allowed values | Add it to the list | The attribute's **Values** tab: type it under **New value** and select **Add** |
| Right, and the attribute should take any value | Turn on **Allow custom values** | The attribute's **Values** tab, under **Options** |
| Wrong, in a file you import by hand | Replace it in the file with one of the allowed values | Your import file |
| Wrong, in files a data source imports for you | Convert or remove it before it is written | The dataset's **Mapping** tab on the data source: open the field's pipeline with the arrow button beside it (pointing at it shows **Edit pipeline**) and add a node that converts the value |

The attribute's **Values** tab is in **Settings → Attributes & sections** for an attribute of a product, and in **Settings → Custom entities** for an attribute of a custom entity — see [Attributes](/en/concepts/attributes.html) and [Custom entity settings](/en/concepts/custom-entities.html#custom-entity-settings).

Then import the file again. Products already imported get the value; custom entity records that were refused are imported.
